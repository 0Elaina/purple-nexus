# Purple Nexus 产品范围

## 1. 文档职责

本文档定义 Purple Nexus 的产品目标、功能边界、开发顺序和验收标准。

本文档不描述技术实现、接口结构、数据库字段、视觉 Token 或 Agent 节点设计。

## 2. 产品定位

Purple Nexus 是一个面向个人开发者和内容创作者的个人品牌、作品、博客与 AI 知识服务中枢。

网站通过统一的内容管理能力沉淀个人作品和技术文章，并进一步将已发布内容构建为知识库，为访客提供具有来源引用的 AI 问答服务。

视觉品牌以紫色、浅青色和未来科技元素为核心，并允许使用或改编相关官方角色、标志、截图、UI、音频和动画素材。Purple Nexus 是个人非商业项目，不代表与原作权利方存在官方合作或授权关系。

## 3. 用户角色

| 角色 | 权限与使用场景 |
| --- | --- |
| 访客 | 浏览个人信息、作品和博客，并使用公开的知识问答功能 |
| 站点所有者 | 管理作品与博客、维护知识库，并查看 AI 服务状态 |

首个版本采用单站点所有者模式，不支持多作者或开放注册。

## 4. 产品目标

- 清晰展示个人身份、技能、作品和技术内容。
- 让站点所有者能够持续维护作品与 Markdown 博客。
- 将已发布博客转化为可检索、可追溯的个人知识库。
- 提供基于站内内容、带来源引用的 AI 问答能力。
- 建立可继续扩展记忆、反思和工具调用能力的 Agent 基础。

## 5. 非目标

首个产品版本不包含：

- 多用户注册、多作者协作和复杂权限系统。
- 评论、点赞、关注、私信等社区功能。
- 付费内容、会员、广告和电子商务功能。
- 原生移动端或桌面客户端。
- 模型训练、微调或自建大语言模型。
- 无限制工具调用、自动发布内容或其他高风险自主操作。
- 使用相关素材开展商业化运营，或宣称与原作权利方存在官方合作。

## 6. 功能范围与开发顺序

| 顺序 | 功能模块 | 验收标准 | 阶段 |
| ---: | --- | --- | --- |
| 1 | 个人主页 | 访客可以了解站点所有者、核心技能和内容入口；桌面端提供完整体验，移动端保证核心内容可用 | 基础版本 |
| 2 | 作品列表 | 访客可以查看已发布作品的列表和详情；页面具备加载、空数据和异常状态 | 基础版本 |
| 3 | 作品管理 | 所有者可以依次完成作品新增、修改和删除；草稿不会出现在公开页面 | 基础版本 |
| 4 | 博客列表 | 访客可以查看已发布文章，并进入文章详情 | 基础版本 |
| 5 | 博客管理 | 所有者可以依次完成 Markdown 文章新增、修改和删除，并控制草稿与发布状态 | 基础版本 |
| 6 | Markdown 阅读 | 正确呈现标题、目录、代码块、图片和常用 Markdown 内容，并适配不同屏幕 | 基础版本 |
| 7 | 博客知识库 | 已发布文章可以进入知识库；文章修改或删除后，知识库结果能够保持一致 | 产品 MVP |
| 8 | RAG 问答 Agent | 回答以公开博客为依据并展示来源；缺少依据时明确说明无法回答 | 产品 MVP |
| 9 | Agent 能力增强 | 支持受控的会话记忆、反思循环和白名单工具调用；关键行为可追踪 | MVP 后 |
| 10 | 管理与系统完善 | 完善管理体验、状态反馈、安全控制和运行可观测性 | MVP 后 |

完成第 1～8 项并通过对应验收标准，视为产品 MVP 完成。第 1～6 项构成内容基础版本，第 9～10 项在 MVP 稳定后继续建设。

作品和博客管理从首次提供写操作起就必须具备最小可用的所有者身份保护。第 10 阶段用于完善管理后台和系统能力，而不是到该阶段才增加访问控制。

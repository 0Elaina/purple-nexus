# Purple Nexus 决策记录

## 1. 文档职责

本文档记录未来可能被追问原因的重要决策，只说明背景、决策和影响，不重复其他设计文档或实现细节。

## 2. 维护规则

- ADR 编号创建后不复用。
- 状态只使用“提议”“已采纳”或“已取代”。
- 已采纳决策不删除；发生变化时新增 ADR，并将旧决策标记为已取代。
- 详细实现以对应设计文档和代码为准，日期与作者以 Git 历史为准。

新增决策使用以下格式：

```markdown
## ADR-XXX：决策标题

- 状态：已采纳
- 背景：为什么需要作出选择。
- 决策：最终选择什么。
- 影响：获得什么，同时承担什么代价。
```

## ADR-001：浏览器不直接调用 AI 服务

- 状态：已采纳
- 背景：公开请求需要统一鉴权、限流、审计和错误处理。
- 决策：React 只访问 Spring Boot，由 Spring Boot 转发 AI 请求。
- 影响：FastAPI 保持内部访问，但 AI 请求增加一层转发。

## ADR-002：业务数据与 AI 派生数据分离

- 状态：已采纳
- 背景：多个服务维护同一业务数据会产生所有权和一致性问题。
- 决策：Spring Boot 和 PostgreSQL 管理业务主数据及所有者长期记忆；FastAPI 和 Qdrant 管理可重建的 AI 索引。
- 影响：数据边界清晰，但跨服务能力必须通过明确契约协作。

## ADR-003：使用 Qdrant 作为独立向量数据库

- 状态：已采纳
- 背景：需要在 pgvector 与独立向量数据库之间选择。
- 决策：使用 Qdrant 保存 Dense、Sparse Vector 和检索元数据。
- 影响：获得独立扩展和混合检索能力，同时增加一个部署组件。

## ADR-004：知识库索引采用 Outbox

- 状态：已采纳
- 背景：博客事务与远程向量索引无法组成可靠的单一事务。
- 决策：博客变更与 Outbox 事件在同一事务提交，后台异步更新索引。
- 影响：支持重试和最终一致性，但发布后可能短暂处于索引处理中。

## ADR-005：服务间首版使用 HTTP

- 状态：已采纳
- 背景：当前规模没有同时维护 REST 与 gRPC 的必要。
- 决策：普通请求使用 REST/JSON，AI 流式响应使用 SSE，Spring Boot 与 FastAPI 使用内部 REST。
- 影响：开发和调试简单；出现明确性能或强类型契约需求后再评估 gRPC。

## ADR-006：采用 Monorepo

- 状态：已采纳
- 背景：前端、核心服务和 AI 服务需要共同演进，同时保持独立构建。
- 决策：三个应用统一放在 `apps/web`、`apps/server` 和 `apps/agent`。
- 影响：跨服务变更可以一次提交，但 CI 必须按变更范围分别构建。

## ADR-007：RAG 使用混合检索

- 状态：已采纳
- 背景：技术博客既包含自然语言语义，也包含类名、API 和错误文本等精确词语。
- 决策：使用 Dense + Sparse Vector，并通过 RRF 融合结果；暂不默认引入 Reranker。
- 影响：检索覆盖更全面，但索引和查询链路比单一向量检索复杂。

## ADR-008：限制 Agent 自主性

- 状态：已采纳
- 背景：无限反思和高权限工具会带来成本、循环和误操作风险。
- 决策：限制反思、检索和工具次数；写操作只返回意图，由 Spring Boot 在所有者确认后执行。
- 影响：Agent 行为更可控和可审计，但不能完全自主完成高风险任务。

## ADR-009：允许使用官方主题素材

- 状态：已采纳
- 背景：项目需要更直接地体现相关角色与游戏主题，并且定位为个人非商业项目。
- 决策：允许使用或改编官方立绘、徽标、截图、UI、音频和动画素材，但不宣称官方合作。
- 影响：主题辨识度更高，同时官方素材需要与原创素材分开管理，便于以后替换。

## ADR-010：采用开放组件与分层动画体系

- 状态：已采纳
- 背景：强二次元界面需要充分控制视觉，同时保留可靠的基础交互与可访问行为。
- 决策：使用 shadcn/ui、Radix Primitives 和 Tailwind CSS 构建组件；Motion 负责常规动效，GSAP 只负责少量重点滚动演出。
- 影响：组件能够深度定制，但必须维护明确的组件归属和动画职责边界。

## ADR-011：桌面视觉体验优先

- 状态：已采纳
- 背景：项目目标是精致、强二次元的个人网站，等权兼顾移动端与加载体积会限制桌面构图和演出。
- 决策：桌面端优先保证视觉完成度与沉浸交互；移动端保证公开核心功能可用，加载性能在视觉方案确定后优化。
- 影响：可以使用更丰富的素材与动效，但移动端体验会简化；动画流畅度和交互响应仍需保证。

## ADR-012：采用 D1-01.2 项目标识与本地基础设施基线

- 状态：已采纳
- 背景：Git 基线、三端脚手架、本地基础设施和 CI 在实施前需要共享唯一且无冲突的项目标识、平台、存储方案和端口约定。
- 决策：
  - 项目名称使用 `Purple Nexus`，仓库名称使用 `purple-nexus`；三端应用标识分别为 `purple-nexus-web`、`purple-nexus-server` 和 `purple-nexus-agent`。
  - 远程仓库采用 GitHub 公开仓库 `0Elaina/purple-nexus`；初始化时保持空仓库，不预置 README、`.gitignore`、许可证或其他初始提交。
  - Java 根包名使用 `com.purple`。该名称仅作为 Purple Nexus 应用内部命名空间，不表示拥有 `purple.com`；未来若发布公共 Java SDK，必须重新评估全局唯一的包名。
  - CI 平台使用 GitHub Actions，远程构建不得依赖开发机私有路径、VM 地址或本地凭据。
  - 本地对象存储使用 RustFS，通过 S3 API 接入并运行在 Ubuntu VMware 虚拟机的 Docker 环境中；它只承担本地开发基础设施职责，业务代码不得依赖 RustFS 专有接口。
  - 开发期应用运行在 Windows，基础设施运行在 Ubuntu Docker。端口采用以下统一矩阵：

    | 服务 | 运行位置 | 端口 | 用途 |
    | --- | --- | ---: | --- |
    | React/Vite Web | Windows | `5173` | 前端开发服务器 |
    | Spring Boot Server | Windows | `8080` | 核心业务 API |
    | FastAPI Agent | Windows | `8000` | AI Agent 内部 API |
    | PostgreSQL | Ubuntu Docker | `5432` | 业务数据库 |
    | Redis | Ubuntu Docker | `6379` | 缓存与状态管理 |
    | Qdrant HTTP/UI | Ubuntu Docker | `6333` | 向量检索与管理界面 |
    | Qdrant gRPC | Ubuntu Docker | `6334` | 向量数据库 gRPC 接口 |
    | RustFS S3 API | Ubuntu Docker | `9000` | 对象存储 S3 接口 |
    | RustFS Console | Ubuntu Docker | `9001` | 对象存储管理界面 |

  - Qdrant 单节点开发环境不发布集群通信端口 `6335`。浏览器只直接访问 Web 与 Spring Boot；VM 地址通过本地环境变量提供，个人地址、绝对路径和凭据不得提交到仓库。
- 影响：D1-02 至 D1-06 可以直接复用同一套仓库、包名、CI、S3 契约和端口输入；采用生态默认端口降低配置成本。`com.purple` 的全局唯一性不受域名所有权保障，因此其适用范围被限制为当前应用。

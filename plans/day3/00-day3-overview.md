# Purple Nexus Day 3 总体任务规划

## 1. 文档职责

本文档定义 Purple Nexus Day 3「作品列表与公开浏览」的总体目标、阶段边界、依赖关系、预期产物、风险和完成标准。

本文档只记录稳定规划，不包含数据库完整字段、接口 JSON、安装命令、依赖版本、组件代码、逐条操作教程、执行进度或排障日志。Day 3 继续遵循：

```text
当前阶段规划 -> 当前阶段执行 -> 下一阶段规划 -> 下一阶段执行
```

本总览只说明各阶段的职责和依赖，不代替对应阶段的详细规划。只有当前阶段执行并通过验收后，才创建下一阶段的详细规划。

## 2. Day 3 入口状态

Day 2 已完成并冻结首页体验：

- 首页已具备 Hero、Nexus、Gateway 和 Footer 的稳定结构。
- Projects、Blog、Agent 入口由统一静态内容表达真实开放状态；未开放入口不生成伪链接。
- 首页具备桌面滚动增强、移动端与 Reduced Motion 静态降级、键盘入口和可见焦点基线。
- 当前 Web 尚无真实子页面、路由和远程业务数据读取。

Day 1 已建立 Server、PostgreSQL、Flyway、MyBatis 和质量门禁基础。Day 3 在这些基础上开发首个业务领域，不重做首页，也不提前建设作品管理、博客或 Agent。

## 3. Day 3 总体目标

Day 3 交付一条可验证的访客作品浏览路径：

1. PostgreSQL 保存作品业务主数据，并能明确区分已发布与非公开状态。
2. Spring Boot 提供只返回已发布作品的列表和详情读取能力。
3. Web 提供作品列表、稳定详情地址以及加载、空数据、异常、成功和不可用详情状态。
4. 首页 Projects 入口连接到真实作品页面，同时保持 Day 2 已冻结的内容和交互语义。
5. Server 与 Web 通过针对性测试和最终综合验收共同证明发布隔离、导航和降级行为。

Day 3 的成功标准不是建立多少表、接口或组件，而是访客能够从首页进入作品列表、打开公开详情，并且任何公开路径都不会泄露未发布作品。

## 4. 工程取舍原则

### 4.1 发布隔离属于 Server

- 公开查询必须在 Spring Boot 查询链路中强制限制为已发布作品。
- Web 不接收草稿后再自行过滤，也不通过客户端参数决定公开边界。
- 不存在与未发布详情采用相同的不可用语义，避免通过公开地址推断草稿是否存在。

### 4.2 按真实业务闭环建立模块

- Server 采用按功能组织的模块化单体，作品职责集中在作品功能模块内。
- 功能模块内部保持 Controller -> Service -> Mapper 分层；启动、全局配置和健康检查保留在应用组装模块。
- 当前只建立真实使用的应用与作品模块，不为博客、Agent 或假设性复用提前创建共享模块。

### 4.3 内容与媒体解耦

- 标题、摘要、详情内容和公开定位不依赖封面才能成立。
- 封面缺失、加载失败或对象存储暂不可用时，核心文本和导航仍然可读可操作。
- Web 不维护第二份作品文案或静态假数据作为业务事实来源。

### 4.4 状态先于装饰

- 列表和详情先建立完整语义、请求状态和普通文档流，再增加符合展示页模式的视觉增强。
- Loading、空数据、异常和不可用详情必须通过可理解的页面内容表达，不依赖动画或控制台日志。
- 动效不能成为发现链接、理解状态或阅读内容的前提。

### 4.5 依赖与抽象按需引入

- 不为当前规模提前建设搜索、分页、缓存、通用数据平台或完整组件库。
- 路由和请求状态优先评估现有 React、浏览器平台与当前依赖；只有真实导航或状态问题无法可靠解决时才引入成熟方案。
- 组件、Hook、Service 和工具函数按当前职责与真实复用拆分，不为目录形式制造薄包装。

## 5. 范围边界

### 5.1 Day 3 包含

- 作品主数据及发布状态约束。
- 已发布作品列表和单项详情的 Server 读取契约。
- 作品列表与详情页面、稳定导航地址和真实 API 数据流。
- 首页 Projects 入口从建设中状态升级为真实可用入口。
- 列表和详情的加载、空数据、异常、成功和不可用状态。
- 封面缺失与媒体失败时的内容降级。
- 桌面与移动端核心可读性、键盘访问、可见焦点和 Reduced Motion 边界。
- 与发布隔离、HTTP 语义、页面状态和导航相关的必要测试与阶段质量验收。

### 5.2 Day 3 不包含

- 作品新增、修改、删除、草稿管理和发布后台。
- 所有者登录、Session、CSRF、上传和管理端权限。
- 博客、Markdown 阅读、知识库、RAG 或 Agent 功能。
- 高级搜索、复杂筛选、推荐、点赞、评论或分页体系。
- 缓存体系、对象存储管理界面和生产部署准备。
- 为未来业务创建空模块、空接口、空页面或未使用依赖。

### D3-01：作品主数据与公开读取契约

建立作品功能模块、业务主数据、发布约束、公开读取投影以及 Controller -> Service -> Mapper 查询链路，并通过针对性 Server 测试证明列表与详情只暴露已发布作品。

预期产物：

- 职责清晰的 Server 应用组装模块与作品功能模块。
- 作品主数据迁移和公开读取模型。
- 已发布列表与详情的稳定 Server 契约。
- 覆盖发布隔离和主要 HTTP 语义的针对性测试。

当前只维护本阶段的详细规划：[`01-public-project-browsing.md`](./01-public-project-browsing.md)。

### D3-02：作品列表与详情浏览

在 D3-01 已验收的真实契约上建立 Web 路由、API 读取适配、列表、详情以及主要请求状态，不修改首页既有场景职责。

预期产物：

- 可复制、可直达并可从列表恢复的作品地址。
- 由真实 API 数据驱动的列表与详情页面。
- 加载、空数据、异常、成功和不可用详情状态。

D3-01 未执行并通过验收前，不创建 D3-02 详细规划，也不修改 Web 作品页面源码。

### D3-03：首页入口接入与综合验收

将首页 Projects Gateway 升级为真实入口，集中完成作品浏览的响应式、键盘、媒体降级、Reduced Motion 和 Day 3 质量门禁。

预期产物：

- 从首页到列表再到详情的完整访客路径。
- 不破坏 Day 2 首页内容、状态联合类型和视觉职责的入口升级。
- Day 3 最终测试、静态检查、构建与浏览器验收结论。

D3-02 未执行并通过验收前，不创建 D3-03 详细规划。

## 7. 职责分工

### 7.1 Server、数据库与基础设施

- 由用户亲自编写和修改作品迁移、模型、Mapper、Service、Controller 与 Server 测试。
- Codex 在每个小任务前讲解目标、运行语义、职责边界和文件影响，提供可执行的局部指导，并在用户完成后检查真实文件和结果。
- Codex 不直接修改后端、数据库或基础设施，除非用户明确授权。

### 7.2 Web

- Web 页面、样式、前端状态和前端测试由 Codex 直接实现。
- Codex 动手前仍需说明目标、运行时行为、文件影响和实现顺序，并按职责片段交错讲解与修改。
- 用户负责产品方向、交互取舍和视觉验收；依赖与 Git 状态相关命令由用户执行。

## 8. 总体预期交付

- 只暴露已发布作品的公开 Server 查询链路。
- 可从首页访问的作品列表与详情页面。
- 清晰且一致的请求、空数据、异常和不可用状态。
- 媒体失败时仍可阅读和操作的作品内容。
- 与当前规模相匹配的 Server/Web 测试。
- 不破坏 Day 2 冻结首页的 Gateway 升级。

不单独创建与源码重复的接口字段清单、数据库字段副本、组件清单或执行日志。

## 9. 总体风险

| 风险 | 影响 | 处理原则 |
| --- | --- | --- |
| 在 Web 中过滤草稿 | API、缓存或直达地址可能泄露未发布内容 | Server 查询链路强制发布隔离 |
| 一次完成 Server、Web 和综合验收 | 教学粒度过大，错误难以定位 | 按契约、浏览界面、综合验收依次推进 |
| 接口字段先于业务语义冻结 | 实现细节反向限制领域边界 | 先固定公开标识、发布语义和失败状态 |
| 为详情提前引入复杂内容模型 | D3-01 被未来管理或博客需求拖大 | 只承载当前公开浏览真实需要的信息 |
| 封面成为页面必要条件 | 媒体异常导致核心内容不可用 | 文本和导航独立成立，媒体只做增强 |
| 首页入口升级时重写 Day 2 场景 | 冻结基线被后续业务反复破坏 | 只修改 Projects 的真实状态与导航关系 |
| 为路由或请求状态过早引入多套方案 | 依赖和维护成本增加 | 先确认真实问题，再选择单一成熟方案 |

## 10. Day 3 完成标准

只有同时满足以下条件，Day 3 才视为完成：

- 访客可以从首页 Projects 入口进入作品列表，并进入公开作品详情。
- 公开列表和详情只返回已发布作品；未发布作品不会通过直达地址泄露任何内容。
- 列表和详情具备可理解的加载、空数据、异常、成功和不可用状态。
- 作品标题、摘要、详情和导航在桌面与移动视口中可读，不产生关键横向溢出。
- 所有真实链接和可操作元素可以通过键盘访问，焦点持续可见。
- 封面缺失、媒体失败或 Reduced Motion 条件不会阻断核心浏览路径。
- Server 与 Web 的测试保护发布隔离、HTTP 语义、页面状态和真实导航。
- 开发指南规定的 Day 3 相关质量门禁全部通过。
- Day 2 首页结构、内容职责、Gateway 状态语义、素材记录和降级基线没有被破坏。
- 没有新增作品管理、认证、博客、Agent 或其他无关能力。

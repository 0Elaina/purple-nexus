## 3. 阶段目标

D2-04 将 D2-03 的桌面主页收口为可在代表性移动视口、键盘操作、Reduced Motion 和完整质量检查下使用的 Day 2 首页切片。

本阶段的核心目标是：

1. 桌面、平板和移动视口不出现关键横向溢出、遮挡或无法离场的场景。
2. 主内容、入口状态、跳过链接、焦点样式和装饰性媒体在键盘与辅助技术语义下保持可理解。
3. Reduced Motion、移动端和媒体加载受限时，页面仍提供完整的静态内容与可操作入口。
4. 对 D2-03 验收中发现的场景承接问题进行必要的局部视觉修正，但不重写 Hero、Nexus、Gateway 的内容职责或叙事顺序。
5. 按开发指南完成 Web 的测试、静态检查、构建和最终浏览器验收。

## 4. 范围边界

### 4.1 本阶段包含

- 首页在代表性桌面、平板和移动视口下的布局、间距、字体、视频裁切、卡片排列和 Footer 收束。
- Header、跳过链接、场景标题、Gateway 卡片和 Footer 的键盘顺序、可见焦点、语义标识和可读性。
- `prefers-reduced-motion` 下 GSAP 时间线不注册或不持续运行，页面内容和状态保持完整。
- 移动端删除或降级复杂滚动演出、视差和过度装饰，保留核心内容和必要反馈。
- 视频加载失败、自动播放受限或媒体不可用时的静态阅读路径。
- Hero、Nexus 与 Gateway 之间的局部色彩和层次修正，只以可读性、场景连续性和响应式表现为依据。
- 当前 Web 的针对性测试补充、静态检查、生产构建和代表性浏览器验收。

### 4.2 本阶段不包含

- 新增 Projects、Blog、Agent 的业务页面、路由、后端接口或真实数据读取。
- 改变 D2-03 已确认的首页文案职责、Gateway 状态语义、4K 视频素材或素材来源记录。
- 引入新的动画库、组件库、粒子引擎、Three.js 或独立设计系统包。
- 重构 D2-02 的主题 Token、公共外壳职责或全站布局架构。
- 完整移动端产品体系、后台管理端适配或生产部署准备。

## 5. 验收工作流

### D2-04-A：建立响应式与媒体降级基线

检查并修正三个场景、Header、Gateway 卡片和 Footer 在代表性桌面、平板和移动视口下的尺寸、排列、裁切、溢出和离场行为；确认视频不是理解 Hero 内容的唯一条件。

预期结果：核心标题、说明、入口状态和 Footer 在不同视口中保持可读，页面不出现横向滚动或关键内容被固定外壳遮挡。

### D2-04-B：完成键盘与无障碍收口

围绕跳过链接、标题层级、场景语义、链接与非链接入口、可见焦点、装饰性媒体和颜色对比度完成必要修正；不为装饰元素制造多余的交互语义。

预期结果：键盘用户可以进入主要内容、识别场景和入口状态，所有真实可操作元素具有持续可见的焦点反馈，建设中条目不会进入链接交互路径。

### D2-04-C：完成动效降级与场景视觉收口

验证桌面动效只在允许的媒体条件下运行，移动端与 Reduced Motion 直接使用稳定静态状态；根据真实浏览器表现修正 Nexus 的纯色块感、Hero 到 Nexus 的色彩承接和不必要的视觉竞争，但不改变既定页面结构。

预期结果：没有持续运动或大幅位移时，页面仍然完整；允许动效时，场景变化可理解、可逆且不会锁住滚动；视觉修正服务于连续性和可读性，而不是扩展新的演出系统。

### D2-04-D：完成质量门禁与综合验收

基于 `docs/03-development-guide.md` 的 Web 质量要求完成测试、静态检查和构建，并在代表性桌面、移动和 Reduced Motion 条件下完成一次综合浏览器验收；清理本阶段产生的无效样式、未使用资源和临时抽象。

预期结果：Web 质量门禁全部通过，首页形成可复现的 Day 2 最终基线，后续功能开发不需要重写当前场景职责或主题基础。

## 6. 工程职责边界

- 页面内容继续由 `homeContent.ts` 统一提供；D2-04 不将文案复制到测试、样式或动画 Hook。
- `HomeHeader`、三个场景和 `HomeFooter` 继续保持页面私有职责，不为了响应式验收提升为站点级组件。
- `useHomeMotion` 继续集中管理 GSAP、ScrollTrigger、媒体条件和清理；场景组件不新增分散的滚动监听。
- CSS 负责响应式布局、静态降级和稳定视觉层次；GSAP 只负责允许动效条件下的连续过渡。
- 测试保护语义结构、入口状态、降级边界和关键交互，不对纯装饰颜色和动画中间值建立脆弱断言。
- 本阶段不新增依赖；如果真实验收发现现有方案无法满足边界，必须先确认再改变技术选型。
- 外部参考只能在确认职责、许可证、包体、可访问性和 Reduced Motion 适配后局部采用；不复制参考站点的整页结构或交互密度。

## 7. 风险与处理原则

| 风险 | 影响 | 处理原则 |
| --- | --- | --- |
| 桌面构图直接压缩到移动端 | 标题、视频和卡片遮挡或溢出 | 为移动端保留语义内容，主动降级裁切、间距和复杂动效 |
| 固定 Header 覆盖内容 | 键盘焦点或锚点位置不可见 | 检查真实视口和焦点滚动位置，保证跳过链接与标题可达 |
| 玻璃、网格和发光过多 | 正文对比度下降、视觉焦点分散 | 优先保证文字和操作反馈，装饰保持低透明度 |
| Reduced Motion 只停掉部分动画 | 页面仍有持续运动或状态不一致 | 由页面私有 Hook 统一受媒体条件控制，静态状态必须独立成立 |
| 媒体加载失败后布局塌陷 | Hero 失去可读背景或内容位置跳动 | 视频只作为装饰层，保留背景色、遮罩和完整文本结构 |
| 为修复局部视觉问题扩大范围 | D2-04 重新设计 D2-03 | 只做响应式、可读性、连续性和验收直接需要的局部修正 |
| 质量命令在用户环境中未执行 | 阶段状态无法确认 | 由用户执行开发指南规定的命令，Codex 根据真实输出解释并修正 |

## 8. 阶段验收标准

D2-04 只有同时满足以下条件才通过：

- 桌面、平板和移动代表性视口下没有关键横向溢出、内容遮挡或无法离开的场景。
- Hero、Nexus、Gateway 和 Footer 的内容顺序、标题层级和入口语义保持稳定。
- Header、跳过链接、真实链接和其他可操作元素可以通过键盘访问，焦点持续可见。
- Projects、Blog、Agent 的建设中状态仍不是伪链接，状态信息清晰可辨。
- Reduced Motion 和移动端不运行复杂滚动时间线，核心内容、入口状态和页面顺序仍完整可用。
- 视频播放失败、自动播放受限或媒体不可用时，Hero 仍能阅读和理解。
- Nexus 场景不再形成无法解释的纯色块或突兀边界，局部视觉修正不改变 D2-03 的叙事职责。
- Footer 在不同视口和滚动状态下可自然到达，固定 Header 不遮挡关键内容。
- Web 测试、静态检查和生产构建遵循 `docs/03-development-guide.md` 的要求并全部通过。
- 首页外部素材、来源记录、非官方声明和现有主题 Token 没有被本阶段破坏或重复维护。

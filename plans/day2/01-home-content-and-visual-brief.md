# D2-01 首页内容与视觉方案规划

## 1. 文档职责

本文档只规划 D2-01“首页内容与视觉方案”的目标、边界、输入、任务、预期产物、风险和验收标准。

本文档不包含最终文案、素材文件清单、字体名称、颜色参数、线框成品、依赖选型结论、安装命令或页面代码。这些内容在用户明确要求执行 D2-01 后，于对话中逐项确认；执行结果不回填为操作日志。

完成本规划只代表 D2-01 已具备执行入口，不代表首页方案已经确认。

## 2. 阶段目标

在编写主页代码前，形成一套足以指导 D2-02 和 D2-03 的首页实现约束：

- 明确首页需要营造的体验、保留的最小信息，以及访客浏览后的下一步。
- 明确主视觉、滚动演出、功能入口和页脚的职责与叙事顺序。
- 明确 Neptune、Purple Heart、Nepgear、Purple Sister 等主题元素在页面中的使用边界。
- 明确桌面主构图、滚动叙事、重点动效和移动端降级方式。
- 判断主页内容应采用静态前端内容还是需要最小后端读取链路。
- 识别真正需要成熟依赖或基础组件解决的交互问题，但不在本阶段提前安装。

本阶段解决的是“要构建什么以及为什么”，不是“如何写出页面”。

## 3. 已知约束

- 首页同时承担欢迎页职责，不设置强制跳过的启动画面。
- 视觉以浅色主题为主，使用丁香紫、浅青、纯白、玻璃、发光和科技纹理。
- 桌面端承载完整构图与演出，移动端保证核心内容和操作可用。
- 首页允许使用或改编官方素材，但项目保持个人非商业性质并明确非官方身份。
- 动画不得劫持滚动，Reduced Motion 必须具备明确降级。
- Day 2 不预设作品、博客、Agent 或管理页的具体布局。
- 当前 Web 只有最小状态页，没有必须兼容的既有业务页面结构。

## 4. 范围边界

### 4.1 本阶段包含

- 首页体验目标和最小信息边界。
- 页面语言、语气和标题层级。
- Purple Nexus 品牌标题、氛围文案和功能入口的内容职责。
- 首页区块顺序及区块之间的叙事关系。
- 官方素材、原创装饰和必要来源信息的分类原则。
- 桌面目标视口与整体构图。
- 字体、渐变、玻璃和发光的视觉方向。
- 重点滚动场景和普通交互动效的职责划分。
- 移动端、键盘访问和 Reduced Motion 的降级原则。
- 静态内容与动态数据的边界判断。
- 后续依赖、组件与代码拆分的决策触发条件。

### 4.2 本阶段不包含

- 安装 Tailwind、shadcn/ui、Radix、Motion、GSAP 或字体包。
- 创建组件、Hook、样式文件、资源目录或数据接口。
- 制作最终视觉稿或实现可运行页面。
- 设计作品、博客、Agent 和管理页面。
- 编写数据库表、后端接口或内容管理能力。
- 为未来主题切换预先设计第二套完整主题。
- 提前决定所有组件和源码目录。

## 5. 输入与前置资料

D2-01 执行时需要围绕以下输入完成确认：

- 首页希望营造的第一印象与情绪。
- 希望访客优先进入的功能或内容。
- 可使用的官方角色素材、截图、徽标、音频或已有原创资源。
- 素材来源、允许的改编方式和声明要求。
- 首页主要语言以及中英文混排偏好。
- 期望重点适配的桌面尺寸和最低移动端宽度。
- 对角色占比、二次元浓度、科技感和信息密度的偏好。

资料暂不完整时，可以先确认内容职责和素材占位规则，但不能用冗长说明或虚构信息填充页面。

## 6. 任务拆分

### D2-01-A：确认首页内容契约

目标：确定访客进入首页后依次经历的视觉场景、需要理解的最小信息以及可以采取的下一步操作。

任务：

- 明确首页以主题视觉和交互完成度展示技术能力，而不是承担个人介绍或教学职责。
- 确认 Purple Nexus 标题、极短氛围文案和功能入口的表达层级。
- 确认主视觉、滚动演出、功能入口和最小页脚的叙事顺序。
- 确认作品、博客和 Agent 等尚未完成入口的展示方式，避免产生已经可用的误导。
- 确认 GitHub 是否作为首版唯一外部入口。
- 明确首版不展示个人经历、技术栈列表、技能图标墙和架构说明。
- 明确稳定内容采用前端静态配置，不为首页建立无必要的后端链路。

预期结果：形成以视觉演出为主体、文字克制且无虚假入口的首页内容结构。

### D2-01-B：确认素材与品牌边界

目标：明确哪些视觉资源承担主题表达，以及如何管理来源和替换风险。

任务：

- 区分官方素材、用户已有素材和需要原创的装饰元素。
- 确认角色、徽标、截图或音频在首页中的用途与优先级。
- 确认素材来源记录和非官方声明所需信息。
- 评估素材分辨率、透明背景、裁切空间和移动端适配条件。
- 识别缺失素材，并确定是替换、弱化还是后续补充。

预期结果：形成可以支持首页构图的素材边界，不因单个资源缺失阻塞整个页面。

### D2-01-C：确认视觉方向

目标：把长期设计原则收敛为首页可执行的视觉方向。

任务：

- 确认首页的角色倾向、色彩氛围和视觉重心。
- 确认标题、正文、标签和装饰文字的字体气质。
- 确认渐变、玻璃、发光、机械边框和数据流纹理的主次关系。
- 明确主要发光焦点，避免所有区域同时高亮。
- 明确正文可读性和主题装饰之间的边界。

预期结果：D2-02 可以据此定义语义 Token，而不依赖临时颜色和样式值。

### D2-01-D：确认桌面构图与滚动叙事

目标：确定首页在桌面端的空间结构和内容出现顺序。

任务：

- 确认目标桌面视口和首屏信息密度。
- 确认 Hero、个人介绍、能力展示、特色入口和结束区域之间的关系。
- 明确导航是页面锚点、真实路由入口还是二者组合。
- 确认哪些区块需要 Sticky、视差、揭示或场景转换。
- 区分叙事必要动效与纯环境装饰。
- 保证页面在无动画状态下仍能按正常文档顺序理解。

预期结果：形成足以指导组件职责和动画选型的桌面页面结构。

### D2-01-E：确认移动端与无障碍降级

目标：在桌面方案确定时同步约束移动端和 Reduced Motion，而不是最后补救。

任务：

- 确认移动端必须保留的核心内容和主要操作。
- 确认可取消的 Sticky、视差、复杂装饰和持续动画。
- 确认移动导航、内容顺序和触控目标的基本要求。
- 确认键盘焦点、装饰图像语义和主题素材替代文本原则。
- 确认 Reduced Motion 下需要移除或替换的动效。

预期结果：桌面演出具有明确的移动端和低动态降级路径。

### D2-01-F：确认实现边界与验收重点

目标：为下一阶段划定依赖引入、组件拆分和数据链路的判断依据。

任务：

- 识别必须由成熟组件或动画方案解决的交互。
- 识别适合使用 CSS、常规 React 状态或浏览器原生能力的部分。
- 判断是否存在需要后端支持的真实主页数据。
- 标记具有独立职责或真实复用潜力的页面区域。
- 明确不应提前抽取的单次装饰和页面私有逻辑。
- 将视觉、内容、交互和降级要求转换为可验证的验收重点。

预期结果：D2-02 可以基于真实需求选择依赖和工程结构，不靠预设技术清单推进。

## 7. 预期产物

- 经用户确认的首页体验结构和最小内容边界。
- 经用户确认的素材与品牌使用边界。
- 经用户确认的桌面构图和滚动叙事。
- 经用户确认的移动端与 Reduced Motion 降级原则。
- 静态内容、动态数据和必要后端能力的边界结论。
- 后续依赖引入、组件抽取和验收的判断依据。

上述执行结论保留在 D2-01 对话和后续实际源码、资源及配置中，不额外创建与本规划或源码重复的说明文档。

## 8. 验收标准

只有同时满足以下条件，D2-01 才视为完成：

- 首页以视觉、动画和交互体现技术能力的目标已经明确。
- 主视觉、滚动演出、功能入口和页脚都有清晰职责，不存在只为填满页面而增加的内容。
- 未完成业务入口不会误导访客认为功能已经可用。
- 首页不展示个人经历、技术栈列表、技能图标墙或教学性架构说明。
- 官方素材、原创素材和来源声明边界清晰。
- 字体、渐变、玻璃、发光和主题装饰形成一致方向。
- 桌面构图、重点动效和正常文档顺序不存在冲突。
- 移动端和 Reduced Motion 具有明确降级方式。
- 已判断主页是否需要动态数据及最小后端链路。
- 已识别依赖引入和组件抽取的真实触发条件。
- D2-02 可以在不重新讨论首页目标和整体构图的情况下开始规划。

## 9. 风险与处理原则

| 风险 | 影响 | 处理原则 |
| --- | --- | --- |
| 最小氛围文案和入口状态未确认 | 视觉结构缺少必要语义 | 只确认必要文字，不增加介绍性内容 |
| 主题素材数量过多 | 页面失去视觉焦点 | 每个场景只保留一个主要角色或发光焦点 |
| 素材来源不明确 | 无法形成可靠声明 | 未确认来源的素材不作为核心依赖 |
| 视觉方向只描述为“科技感” | 实现时产生大量主观分歧 | 明确角色、色彩、构图和动效职责 |
| 首页入口对应功能尚未完成 | 访客进入不可用页面 | 使用真实可用入口或清楚标记状态 |
| 过早锁定依赖 | 技术方案反过来限制页面 | 先确认交互，再选择成熟方案 |
| 为避免复杂度而拒绝合理拆分 | 页面组件难以理解和维护 | 按职责与真实复用正常抽取 |
| 为追求工程感提前建设后端 | 增加无效数据链路 | 只为真实动态数据需求引入 |

## 10. 阻塞条件

出现以下任一情况时，不进入 D2-02：

- 首页体验目标或核心场景顺序无法确认。
- 必要氛围文案或功能入口状态无法确认。
- 首页构图依赖的核心素材无法使用且没有替代方向。
- 桌面主方案无法给出移动端或 Reduced Motion 降级。
- 尚未判断未完成业务入口如何呈现。
- 仍在同时竞争多套相互冲突的视觉方向。

### D2-01-E：移动端与无障碍降级

- [x] 移动端复用桌面端相同的 React 组件、内容结构和角色素材，不建立独立移动端页面或第二套组件树。

- [x] 移动端与 `prefers-reduced-motion` 尽量复用同一套静态降级路径，避免维护两套降级逻辑。
- [x] 首版只维护一个主要移动端布局断点，具体值在实现时结合实际构图和 Tailwind 默认断点确定，不提前建立多段设备特判。
- [x] 以 `390 CSS px` 宽度作为移动端主要检查尺寸，并保证 `320 CSS px` 下核心内容和操作不发生关键横向溢出。

- [x] 装饰图像不进入无障碍树，有内容意义的图像提供简短替代文本，图标按钮提供可访问名称。

### D2-01-F：实现边界与验收重点

- [x] Day 2 首页继续使用 Tailwind CSS，并在 D2-02 实际进入页面实现时按需引入，不为规划阶段提前安装依赖。

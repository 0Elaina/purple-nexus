# D2-02 主题基础与公共外壳规划

## 1. 文档职责

本文档只规划 D2-02“主题基础与公共外壳”的目标、边界、依赖判断、任务拆分、预期产物、风险和验收标准。

本文档不包含安装命令、依赖版本、Tailwind 配置内容、具体 Token 数值、字体名称、组件代码、逐条操作教程或执行日志。

D2-02 规划完成后必须停下来等待用户确认；在用户明确要求执行前，不安装依赖、不修改 Web 源码，也不规划 D2-03 的具体实现。

## 2. 上游输入与当前基线

### 2.1 D2-01 已确认输入

- 首页采用“首屏双主角 → 主题界面转化 → 功能入口”的三段式结构。
- 页面以浅色主题为主体，使用珍珠白、丁香紫、浅青、玻璃和受控发光。
- Tailwind CSS 负责布局、响应式、排版和常规状态；复杂视觉效果可以直接使用普通 CSS。
- 主题颜色、光效、圆角和层级等共享参数通过统一语义 Token 管理。
- Header、Footer 和首页动画暂时属于首页私有职责，出现第二个真实消费者后再考虑上提。
- 首页内容使用静态配置，不建立后端接口、远程数据状态或路由体系。
- GSAP、ScrollTrigger 和官方 React 集成只在 D2-03 首次实现重点动画时引入。

### 2.2 Web 当前状态

- Web 已具备 React、TypeScript、Vite、Vitest 和 Testing Library 基线。
- `App` 当前只渲染最小状态页，尚未形成正式首页结构。
- 全局 CSS 只有基础重置与临时颜色，尚未建立 Purple Nexus 语义 Token。
- 当前没有 Tailwind、组件库、图标库、路由库或动画依赖。
- 现有测试只验证 `Purple Nexus` 一级标题，可以在本阶段重构为真实页面外壳测试。

## 3. 本步目标

D2-02 要交付第一个真实可用的前端视觉基础切片：

1. 让 Tailwind CSS 与现有 Vite 工程完成最小、可靠的集成。
2. 将已确认的主题方向落为集中维护、能被 Tailwind 与普通 CSS 共同使用的语义 Token。
3. 建立真实的 `HomePage`、Header、主内容区域和 Footer，不继续把页面结构堆在 `App` 中。
4. 让页面外壳首次体现 Purple Nexus 的主题气质、焦点规则和非官方项目声明。
5. 通过一次针对性自动验证和必要的浏览器检查，证明主题基础与页面语义可用。

本步不是建立完整设计系统，也不是制作三段首页内容。成功标准是 D2-03 可以直接在稳定的主题与外壳上实现主视觉和滚动场景。

## 4. 实施原则

### 4.1 围绕首个真实页面建立基础

- 只定义 Header、Footer、页面背景和下一步首页场景已经明确需要的 Token。
- 不复制 Tailwind 已有的完整间距、尺寸或断点体系。
- 不建设没有当前消费者的通用 Button、Card、Dialog 或动画组件目录。
- 不制作只为展示 Token 而存在、完成后会被删除的样式预览页。

### 4.2 Token 是唯一共享视觉来源

- 颜色、字体、圆角、玻璃、边界、焦点和必要光效使用语义名称表达用途。
- Tailwind 工具类与普通 CSS 必须引用同一组底层 CSS 变量，不维护两份颜色或效果配置。
- 页面组件不散落临时品牌色、阴影和渐变数值。
- Tailwind 默认值能够满足普通布局时直接使用，不为统一形式重复声明。

### 4.3 页面私有优先

- `HomePage` 负责当前首页结构，`HomeHeader` 和 `HomeFooter` 暂时放在首页目录内。
- 不提前创建通用 `AppLayout`、`PublicLayout` 或 `shared` 品牌包装层。
- `App` 只承担应用入口职责，不包含首页具体视觉结构。
- 当后续真实页面需要复用 Header 或 Footer 时，再根据共同需求上提。

### 4.4 依赖按首次使用引入

- 本阶段只引入 Tailwind CSS 及其现有 Vite 工程所需的官方集成。
- 字体只有在确认具体方案且页面立即使用时，才采用适合的自托管文件或成熟字体包。
- Header 和 Footer 首版使用原生语义元素与普通链接能力，不需要为此引入 shadcn/ui 或 Radix。
- 本阶段不引入 GSAP、`@gsap/react`、Motion、图标库、路由、Axios 或 React Query。

## 5. 范围边界

### 5.1 本步包含

- Tailwind 与 Vite 的最小集成。
- 首页当前需要的语义主题 Token。
- 必要的字体方案与基础排版规则。
- 全局背景、默认文字、选择状态、焦点和 Reduced Motion 基线。
- `App`、`HomePage`、`HomeHeader` 和 `HomeFooter` 的职责调整。
- 页面 `header`、`main`、`footer` 语义结构和跳至主内容能力。
- 页脚中的个人非商业、非官方项目声明。
- 清理被真实页面外壳取代的占位结构和无用样式。
- 一个覆盖页面外壳核心语义的针对性组件测试。
- 对 Tailwind 生效、桌面外壳和移动端基本溢出的必要检查。

### 5.2 本步不包含

- `HeroScene`、`NexusTransitionScene` 和 `GatewayScene` 的正式实现。
- Purple Heart、Purple Sister、Next Purple 等角色素材接入。
- 复杂渐变场景、角色构图、滚动时间线和 Sticky 演出。
- GSAP、ScrollTrigger、`@gsap/react` 或 Motion。
- 作品、博客、Agent 的真实路由或伪链接。
- shadcn/ui、Radix、图标库或完整基础组件集合。
- Spring Boot、FastAPI、Axios、React Query 或任何首页接口。
- Storybook、视觉回归、E2E、性能监控或完整设计系统文档。

## 6. 任务拆分

D2-02 是一个完整实现切片。以下内容按职责分段讲解和编写，但不机械拆成多个独立阶段。

### D2-02-A：接入样式基础并建立最小 Token

任务：

- 按现有 Vite 工程选择 Tailwind 的官方集成方式。
- 确认标题与正文的实际字体方案、加载方式和回退字体。
- 建立首页实际需要的颜色、文字、边界、焦点、圆角、玻璃和光效 Token。
- 让 Tailwind 和页面私有 CSS 可以引用同一组语义值。
- 保留必要的浏览器基础样式，移除只服务于旧状态页的临时视觉值。

预期结果：页面可以使用语义化 Tailwind 工具与普通 CSS 表达同一套 Purple Nexus 主题。

### D2-02-B：建立真实首页外壳

任务：

- 将 `App` 收敛为应用入口，由它渲染 `HomePage`。
- 建立页面私有的 `HomeHeader` 与 `HomeFooter`。
- 使用原生 `header`、`main`、`footer` 和标题层级形成稳定页面语义。
- Header 只保留当前真实成立的品牌与页面操作，不链接尚未存在的功能页。
- 主内容区域保留真实的 `Purple Nexus` 一级标题作为 D2-03 的承接点，不增加会被丢弃的预览组件或虚构介绍区。
- Footer 提供必要的非官方、个人非商业项目声明，不扩展为信息密集的站点地图。
- 增加键盘可用的跳至主内容入口和清晰的 `focus-visible` 表现。

预期结果：即使首页主体场景尚未实现，应用也已经具备真实、可访问、可继续扩展的主题外壳。

### D2-02-C：完成针对性验证与清理

任务：

- 将旧状态页测试改为页面外壳测试，验证一级标题、Header、主内容区域、Footer 和非官方声明。
- 证明 Tailwind 实际参与构建并能驱动页面外壳样式。
- 在主要桌面视口和 `390 CSS px` 宽度检查 Header、主内容和 Footer，不处理 D2-03 才会出现的角色构图问题。
- 清理不再使用的占位结构、CSS 选择器和导入。
- 确认没有加入未使用依赖、空公共组件目录或未来页面骨架。

预期结果：主题基础和页面外壳有一个自动化语义证明，并能在浏览器中作为 D2-03 的稳定起点。

- Header 不提供通往未完成页面的伪导航。

- 旧状态页样式和无用导入已经清理。

- 没有引入 GSAP、Motion、组件库、图标库、路由或远程数据依赖。

- Tailwind 集成只做一次能够证明样式参与真实构建的验证。
- 页面外壳只保留一个针对性组件测试，不为纯装饰细节增加快照或脆弱断言。
- 浏览器只检查本阶段可观察的外壳、焦点与基本响应式，不提前验收角色素材和滚动演出。
- 完整 `lint`、全部测试和生产构建继续在 Day 2 阶段结束时集中执行；本阶段不重复运行多套等价证明。

## 11. 风险与处理原则

| 风险 | 影响 | 处理原则 |
| --- | --- | --- |
| 把 Tailwind 当作所有视觉效果的唯一表达方式 | JSX 类名冗长且复杂场景难维护 | Tailwind 负责通用规则，独特效果保留普通 CSS |
| Token 复制 Tailwind 全部默认值 | 配置庞大且没有真实收益 | 只覆盖品牌语义与页面真实需求 |
| Token 与普通 CSS 各自保存一套颜色 | 主题调整时产生漂移 | 共同引用唯一底层变量 |
| 为 Header 提前引入菜单或组件库 | 增加无用依赖和交互状态 | 首版使用原生语义结构 |
| 为未来页面建立通用 Layout | 抽象没有第二个消费者 | 先保持首页私有，真实复用后上提 |
| 为验证主题制作临时展示页 | 产生很快被删除的代码 | 直接在真实 Header、Footer 和页面背景中验证 |
| 字体只追求装饰性 | 中文、正文或操作文字难读 | 标题强调主题，正文保证清晰并提供可靠回退 |
| 全局样式覆盖范围过大 | 后续博客和管理页面难以独立设计 | 全局只放基础行为，页面视觉保持局部 |

## 12. 阻塞条件

出现以下任一情况时，不进入 D2-03：

- Tailwind 与语义 Token 无法共享同一套主题来源。
- 字体方案无法覆盖实际中英文内容或缺少可靠回退。
- 页面外壳仍与旧状态页结构混杂。
- Header 或 Footer 依赖尚未存在的页面、接口或组件系统。
- 页面语义、键盘焦点或移动端基本布局没有通过验收。
- 存在未使用依赖、空抽象目录或为了未来功能创建的占位代码。
